# FUTURE WORK — EES (`ELEK-QUAL-STD-0000`)

Speculative and uncommitted proposals. These are ideas, not plans; none is approved.

- **Automated ELEK-ID allocator.** A small tool/registry that issues the next free
  sequence number per `<DOM>-<SUB>` and prevents collisions, backed by the derived
  `ELEK-<DOM>-<SUB>-<SEQ>-v<VERSION>` template.
- **Evidence-ledger integration.** Wire `EVI-*` references in metadata to the Build
  Engine's append-only EvidenceLedger so evidence attachments are hash-anchored rather
  than free-text paths.
- **Battery Passport as a first-class schema.** Promote §5.2 into a
  `battery-passport.schema.json` enforcing the five mandatory evidence attachments
  before a `BATT-*` can reach a certified state.
- **ECO workflow tooling.** A template + state machine for Engineering Change Orders
  (`ECO-*`) mirroring the §7.2 approval matrix, so modifying a VALIDATED asset
  mechanically requires the right sign-offs.
- **Cross-volume traceability graph.** Machine-checkable digital-thread links (§4) so
  a broken chain flags Non-Compliant automatically.
- **Renderer choice.** Decide whether the presentation HTML is generated by a repo
  script (deterministic, reviewable) or by an external publishing step; current HTML
  was hand-authored and should eventually be generator-produced.
- **Glossary as data.** Extract §8 into a structured glossary file reused across all
  EEA volumes.

Anything here that becomes committed work moves to `ROADMAP.md` with a decision.
